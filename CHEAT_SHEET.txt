═══════════════════════════════════════════════════════════
📚 WHAT EACH SCRIPT DOES
═══════════════════════════════════════════════════════════

setup-kafka-docker.bat
──────────────────────
• Downloads Kafka Docker image
• Starts Kafka container on port 9092
• Configures for localhost
• Run ONCE (one-time setup)
• Takes ~2-3 minutes (downloading)

configure-local-kafka.bat
─────────────────────────
• Updates backend/.env file
• Changes KAFKA_BROKER to localhost:9092
• Clears KAFKA_USERNAME and KAFKA_PASSWORD
• Creates backup of original .env
• Run ONCE (one-time setup)
• Takes ~5 seconds

start-all-offline.bat
─────────────────────
• Starts Kafka (if not running)
• Opens Terminal 1: Backend Server (port 3000)
• Opens Terminal 2: Kafka Consumer (message processor)
• Run DAILY (every time you use MonkiHub)
• Takes ~10 seconds
• Keep both windows open!

test-kafka.bat
──────────────
• Tests if Kafka is running
• Checks port 9092
• Tests Node.js connection
• Run if you have issues
• Diagnostic tool

🆘 TROUBLESHOOTING
═══════════════════════════════════════════════════════════

Problem: Docker is not running
Solution:
  1. Open Docker Desktop from Start Menu
  2. Wait for whale icon in system tray
  3. Wait for icon to stop animating
  4. Try again

Problem: Port 9092 already in use
Solution:
  docker stop monkihub-kafka
  docker rm monkihub-kafka
  setup-kafka-docker.bat

Problem: Consumer not connecting
Solution:
  1. Wait 30 seconds after starting Kafka
  2. Close Consumer window
  3. Run start-all-offline.bat again

Problem: Chat not working
Solution:
  1. Check both terminals are running
  2. Consumer should show "Connected to Kafka"
  3. If not: docker restart monkihub-kafka
  4. Wait 30 seconds and restart consumer

Problem: Backend can't connect to Kafka
Solution:
  1. Check backend/.env file
  2. Should have: KAFKA_BROKER=localhost:9092
  3. Should have: KAFKA_USERNAME= (empty)
  4. Should have: KAFKA_PASSWORD= (empty)
  5. If not, run: configure-local-kafka.bat

What is Kafka?
──────────────
Apache Kafka is a MESSAGE BROKER - it acts as a middleman
between message senders (producers) and receivers (consumers).

Why use Kafka?
──────────────
1. Message Persistence - Messages saved, not lost if crash
2. Decoupling - Producer and consumer work independently
3. Scalability - Can add multiple consumers
4. Fault Tolerance - No message loss
5. Industry Standard - Used by LinkedIn, Uber, Netflix

How MonkiHub uses Kafka:
────────────────────────
User A sends message
    ↓
Backend (Producer) publishes to Kafka topic
    ↓
Kafka stores message in queue
    ↓
Consumer reads from Kafka
    ↓
Consumer saves to XML database
    ↓
Consumer delivers via Socket.IO
    ↓
User B receives message

Key Files:
──────────
• backend/services/brokerService.js  (Producer)
• backend/scripts/consumer.js        (Consumer)
• backend/controllers/messageController.js (API)
• backend/.env                       (Configuration)

Benefits Demonstrated:
──────────────────────
1. Asynchronous Processing - Messages processed independently
2. Message Queue - Messages wait if consumer is down
3. Fault Tolerance - Messages survive server restarts
4. Scalability - Can add multiple consumers

Demonstration Scenarios:
────────────────────────
Demo 1: Normal Flow
  • Start everything
  • Send message from User A
  • User B receives instantly
  • Show message went through Kafka

Demo 2: Consumer Failure (Fault Tolerance)
  • Send message from User A
  • Stop consumer (simulate crash)
  • Message stored in Kafka but not delivered
  • Restart consumer
  • Consumer processes queued message
  • User B receives message
  • PROVES: Message persistence in Kafka

Demo 3: Message Queue
  • Stop consumer
  • Send 5 messages from User A
  • Messages queue up in Kafka
  • Start consumer
  • All 5 messages processed in order
  • PROVES: Queue behavior
